# 比對演算法比較（bake-off）

**目的**：用今晚測試實驗室收集的資料，同時跑多種演算法，找出最能分辨「本人」和「模仿者」的那一個，並且確認結果不是碰巧調出來的。

候選清單是第一版，背景的文獻研究完成後，A 會再補上有研究支持的候選。

## 規則（所有演算法都一樣）

1. **同一個介面**：每個演算法都是 `tools/tuning/algorithms.py` 裡的一個函式：
   ```python
   def score(attempt: Attempt, templates: list[Attempt]) -> float   # 越小越像本人
   ```
   全部登記在 `ALGORITHMS = {"baseline": baseline, ...}`。
2. **門檻用同一套規則**：門檻 = 倍數 × 「三個註冊樣本兩兩之間，用同一個演算法算出的最大距離」，跟 App 一樣。這樣每個演算法都能直接比較，換到 App 上也一樣能用。
3. **不能拿考題來調參數**：
   - 所有可以調的參數，例如倍數、權重，**只能用 S1-tonight 的資料決定**。
   - 決定好之後固定下來，**拿 S2-midnight 和 S3-morning 的資料算成績**。
   - 報告裡兩個數字都要列，但比較時只看 S2 和 S3。
4. **主要方法已經凍結**：`baseline`（倍數 1.25）是主要方法，**最多只比三個事先指名的挑戰者**：`gyro_x2`、`normalized_nfm`、`dtw_plus_global`（原型上的參考實作在 `tools/tuning/quick_candidates.py`）。其他候選只當探索，不列入「要不要換」的決定。
   - **挑戰者只有同時符合下面三點才換到 App 上**：
     1. 用同一批本人嘗試配對比較，本人被拒絕的次數不比 `baseline` 多
     2. S1 定出的門檻在 S2、S3 仍然成立
     3. 在 S3 的 A4 和所有 A3 上，接受的模仿比 `baseline` 少，且配對差距達到 7:0（同時比三個挑戰者時，McNemar 檢定要達到這個程度才有意義）
   - **獨立審查的提醒**：在原型資料上，只看 AUC 的話 `dtw_plus_global` 最好；但用「S1 定門檻、套到 S2」的方式測，它放過了 11/14 的模仿（`baseline` 只放過 2/14）。所以**一定要用實際門檻測，不能只看 AUC**。
   - 實際上最可能的結果是維持 `baseline`。這本身就是可以拿給評審看的嚴謹過程。
5. **資料不 commit**：資料放在 repo 外面，只 commit 程式和報告。
6. **先凍結再看成績**：S1 調出來的設定（演算法、倍數、權重）要在 S2 開始前 commit 並寫上時間，之後不再改動。這是生物辨識評估標準要求的做法（NPL 的 Mansfield & Wayman 2002），評審問起來有依據。
7. **每台裝置的取樣率要分開看**：我們在 AirPods Pro 3 上量到每秒 50 筆，但多數文獻寫 AirPods 最高每秒 25 筆。用記錄的時間戳記算出 Mac 1 和 Mac 2 的實際取樣率寫進報告。如果兩邊不同，加一個候選 `resampled`：DTW 前先把每次簽名重新取樣到固定的每秒 25 筆。
8. **模仿者的數字分開報**：A2 隨便亂簽算錯誤接受率（FAR）；A3、A4 是刻意攻擊，依 ISO/IEC 30107-3 的做法單獨列成「攻擊成功率」，不要跟 FAR 混在一起。區間用 Wilson 95%；只有 2 位本人，不要宣稱能推論到一般人口。

## 候選演算法（第一版）

| 名稱 | 做法 | 想驗證什麼 |
|---|---|---|
| `baseline` | 目前 App 的做法：9 維特徵、band 0.25 的 DTW、時長加權、取三個樣本中的最小值 | 比較基準 |
| `gyro_x2` | 陀螺儀權重加倍（`FeatureScale.rotation` 3 → 1.5） | C 用原型資料調出來的建議，在新資料上還成立嗎 |
| `mean_templates` | 三個樣本的平均距離，取代最小值 | 取最小值會不會讓模仿者太容易「撞到」其中一個 |
| `dtw_independent` | 握法、加速度、陀螺儀三組各自做 DTW 再相加，取代合在一起做 | 各組各自對齊會不會更準 |
| `derivative_fusion` | 0.5 × DTW(原訊號) + 0.5 × DTW(相鄰兩筆的差值) | 加入「變化的速度」，能不能抓到模仿者學不來的節奏 |
| `global_features` | 每次簽名算一組整體特徵：時長、各軸 RMS、陀螺儀過零次數、峰值數、路徑長度、8–12 Hz 頻帶能量。用註冊樣本的平均和標準差做標準化距離 | 不看時間對齊、只看整體特性的方法表現如何 |
| `dtw_plus_global` | 把 `baseline` 和 `global_features` 各自除以「註冊樣本之間的距離」後相加 | 兩種方法互補，能不能贏過單獨一種 |
| `tremor_only` | 只用 8–12 Hz 頻帶能量（手的生理性顫抖） | 顫抖本身能不能分辨人。文獻認為辨識力弱又不穩定（同一人也會差 5–20 倍），比較適合判斷「是不是真人在拿」，所以權重要低 |
| `kinematic` | **（文獻）** 每段的速度變化、正規化後的急動度（jerk）、停頓次數、DTW 對齊路徑的統計，再跟 `baseline` 用註冊樣本正規化後相加 | 文獻上偽造者學得會形狀、學不會力道和速度。有研究在軌跡比對之外加入手部動作特徵後，看影片學的偽造被擋下的比例從 65.9% 提高到 98.4% |
| `normalized_nfm` | **（文獻）** 算出跟最近、最遠、中位樣本的三個距離，各自除以「註冊樣本之間」對應的平均距離（設下限避免除以接近 0），三者相加，門檻是 S1 調出的一個全域常數 | SVC2004 簽名比賽冠軍的做法（Kholmatov & Yanikoglu），在手寫板上讓熟練偽造的錯誤率從 4.37% 降到 2.84% |
| `fusion_sum` | **（文獻）** 下面三者各自用註冊樣本正規化後相加：9 維一起做的 DTW、握法／加速度／陀螺儀分開做的 DTW、整體特徵距離 | 文獻上加入整體特徵後，錯誤率最多減少約 25%，註冊樣本少時效果最明顯 |
| `template_update` | **（文獻）** 以 `baseline` 為底，把 S1 裡分數遠低於門檻的本人嘗試（最多 2 次）加進註冊樣本，模擬註冊 5 次和自動更新樣本 | 文獻上註冊樣本從 1 個增加到 4 個，錯誤率從 22.4% 降到 12.5%；樣本更新對跨時段的穩定度最有幫助 |

**不要用的做法**（文獻上會讓熟練偽造的結果變差）：用冒充者的分數做 z-score 正規化、把每個軸各自標準化（z-score）。

## 要產出的報告：`docs/algorithm-comparison.md`

1. **主表**：每個演算法一列，欄位如下：
   - S2+S3 的本人通過率
   - A2、A3、A4 的模仿者通過率
   - A4 的 AUC
   - EER
   - S1 調出來的倍數
2. **A4 練習過的模仿者這一欄最重要**：如果有演算法在 A4 是 0 次通過，也要寫出它的 95% 上限（三分之一法則）。
3. **建議**：最多 2 個值得換到 App 上的改動，每個都說明：
   - 在 S2 和 S3 上贏多少
   - Swift 要改哪幾行
   - 改不改得完。交件是 12:00，所以任何改動都要在 **09:30 前**確定。
