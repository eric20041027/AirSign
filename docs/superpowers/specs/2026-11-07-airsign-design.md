# AirSign 設計文件

- 日期：2026-11-07（MakeUC 2026，Security 類別）
- 狀態：草稿，等使用者核准
- 標記方式：**（使用者決定）** 是使用者在討論中說的；**（Claude 決定）** 是我替他做的預設，可以被推翻；沒標記的是背景事實或實測結果。

## 一句話

手握一顆 AirPod 在空中簽名，就能替 Mac 上的任何檔案上鎖。只有你的 AirPod、你的握法和你的簽名節奏打得開它。

## 為什麼要做

**問題**（使用者決定）
- 密碼會外洩、會被重複使用；很多人已經不相信密碼，或擔心自己的密碼早就外洩了。
- 很多筆電沒有指紋辨識，只能輸入密碼。
- 有些重視資安的人不願意把指紋這種身體特徵用在電腦上，不只是不信任 Apple，任何品牌都一樣。

**給誰用**（使用者決定）
- 不信任密碼、想多一層保障的人
- 想找其他加密方式的人
- 不願意在電腦上使用身體生物特徵的人

**為什麼不用 Touch ID 或密碼**（使用者的論點，Q&A 與 Devpost 都要用）
1. 不需要指紋辨識硬體。
2. 指紋一輩子只有一組，外洩就無法更換；空中簽名外洩了可以換一個新的。
3. 偷不走：指紋會留在杯子和螢幕上被採下來複製，手腕轉動的節奏不會留下痕跡。
4. 所有資料只留在這台電腦上，不上傳。

**要誠實的地方**：Touch ID 的指紋資料其實存在 Mac 的安全晶片裡，不會上傳給 Apple，所以 pitch 要用上面四點，不要說「大公司會偷指紋」。第一版只支援 macOS，「其他品牌筆電」是未來工作。

**比賽脈絡**
- 交件期限：2026-11-08 12:00（美東時間）。之後在 Discord 遠端評審：5 分鐘 demo 加 5 分鐘問答，評審看螢幕分享，不能親手試用。
- 評分四項：Concept、Technical Execution、Technical Demonstration（要展示成功、失敗與限制）、Presentation（照規定交件，包含 demo 影片長度）。
- Security 類別評審想看：真實的安全問題、保護使用者資料、攻防情境展示、威脅建模與部署建議。
- 誠信規則：專案必須在 24 小時內從零開始。`spikes/airpods-motion/` 是本次比賽期間做的原型，可以當參考，正式程式另外寫。

## 目標（demo 一定要有）

1. **註冊**：在 AirSign 裡用慣用手的那顆 AirPod 簽 3 次，建立簽名樣本。
2. **上鎖**：在 Finder 對檔案按右鍵選「Lock with AirSign」，檔案變成 `原檔名.airsign`。（使用者決定：右鍵選單優先）
3. **解鎖**：對 `.airsign` 檔案按右鍵選「Unlock with AirSign」，跳出簽名視窗，簽名通過就還原成原檔案。
4. **多道關卡**（使用者決定）：關卡 1 是硬性關卡，沒過就直接拒絕。關卡 2–4 跟原型一樣合成一個總分（DTW，時長也算在內），用總分決定通不通過；畫面上的關卡燈號只用來顯示哪一道跟註冊樣本差最多。理由：實測只證明「總分」分得開，各關卡單獨判斷時分辨力只有 AUC 0.91–0.93，四道各自要過會讓本人常被擋。
   - 關卡 1：**用的是註冊時那副 AirPods 的那一顆**（慣用右手用右耳那顆，左撇子用左耳那顆）。動作資料只說得出左耳或右耳，所以「是不是同一副」改用系統音訊輸出裝置的 UID 判斷（CoreAudio，不需要額外權限）。（Claude 決定，實作時要先驗證 UID 對 AirPods 是否穩定；做不到就把 pitch 改成「你那一側的 AirPod」）
   - 關卡 2：**握法和簽名平面**（AirPod 的傾斜角度變化，也就是在水平面還是垂直面簽）
   - 關卡 3：**簽名幅度和長度**（加速度與簽名時間）
   - 關卡 4：**手腕轉動的節奏**（陀螺儀）。這是旁人唯一看不出來的一道。
5. **防暴力破解**：連續失敗 5 次，鎖住 5 分鐘。（Claude 決定）
6. **畫面看得懂**：簽名時即時畫出簽名路徑、四道關卡的燈號和分數，讓螢幕分享的評審一眼看懂。
7. **更換簽名**：可以重新註冊新的簽名；舊檔案不需要重新加密，用新簽名就能打開。
8. **救援碼**（使用者決定）：註冊時只顯示一次救援碼，像兩步驟驗證的備用碼。AirPods 掉了或簽不出來時，用救援碼能在任何裝了 AirSign 的 Mac 上打開 `.airsign` 檔。救援碼不存在 Mac 上，請使用者抄下來或印出來。

## 非目標

- Windows、Linux：讀 AirPods 動作資料的 API 只有 Apple 平台有。未來可以讓 iPhone 當中繼。
- 從簽名直接產生加密金鑰（fuzzy extractor）：研究等級的做法，17 小時內做不完，列為未來工作。
- 雲端同步、多使用者、把上鎖的檔案分享給別人。
- 資料夾上鎖（第一版只處理單一檔案）。（Claude 決定）
- 正式的 Finder 外掛（Finder Sync Extension）：只有時間夠才做。（使用者決定：時間允許再做 App）

## 反目標（就算能動也算失敗）

- **弄丟使用者的檔案**：上鎖時必須先寫好 `.airsign`、在記憶體中解密驗證內容一致，才能移除原檔。
- **本人常常被拒絕**：demo 會很難看。彩排時本人 10 次至少要過 9 次。
- **宣稱做不到的安全性**：例如說「簽名就是金鑰」。威脅模型要誠實寫出限制。
- **資料離開這台 Mac**：除了本機以外，不發出任何網路連線。

## 限制

- **硬體**（使用者提供）：
  - Mac 1：MacBook Pro，macOS 26.5、Xcode 26.5，主力開發機
  - Mac 2：MacBook Air M1（macOS 版本待確認，需要 14 以上），有免費版 Antigravity
  - Windows 11 電腦（RTX 5060），有另一個 Claude Max 帳號；不能建置或執行 macOS App
  - AirPods Pro 3 和 AirPods 4 各一副，兩副都有頭部追蹤，所以兩台 Mac 可以各接一副同時開發與測試
  - 一支 iPhone
- **AirPods 的行為**（原型實測）：
  - 同一時間只有一顆送資料，每筆資料會標明是左耳還是右耳。
  - 每秒 50 筆，App 在背景時照樣送。
  - 握在手上時，**手指必須蓋住入耳感測器**才會持續送資料。另一顆要放在充電盒裡。
- **時間**：大約 17 小時可用，還要留時間錄 demo 影片、寫 Devpost、填評審報名表。
- **隊伍**：3 人，熟 TypeScript/React/three.js、Python、C#/Unity，Swift 經驗未知。Windows 那台只能做不需要 Mac 的工作，例如用 Python 調整比對參數、寫 Devpost、剪 demo 影片。
- **簽署**（使用者提供）：只有免費 Apple ID，沒有付費開發者帳號（每年 99 美元，申請也要等待審核，比賽期間不考慮）。用 Xcode 的免費個人團隊簽署。

## 使用者流程

1. **第一次使用**：打開 AirSign，跟著指示用慣用手捏住 AirPod、手指蓋住感測器，簽 3 次（每次約 2 秒）。系統記下是哪一副 AirPods 的哪一顆，自動算出門檻，最後顯示一次救援碼，請使用者抄下來並確認。
2. **上鎖**：右鍵選「Lock with AirSign」，不需要簽名。（Claude 決定：上鎖像壓縮檔案一樣方便，解鎖才需要本人）
3. **解鎖**：右鍵選「Unlock with AirSign」，跳出簽名視窗，按空白鍵後簽名，停住不動就自動結束。結果分三種：
   - 四道關卡全過：還原原檔
   - 沒過：顯示「無法辨識」，失敗次數加 1
   - 動作中斷（手指滑開、換成另一顆、沒有資料）：這次不算，請使用者重簽
4. **連續失敗 5 次**：顯示倒數，5 分鐘內不接受簽名。
5. **更換簽名**：在 AirSign 裡選「重新註冊」，要先用目前的簽名或救援碼通過一次才能換。
6. **用救援碼開檔**：簽名視窗裡有「改用救援碼」，輸入正確的救援碼就還原檔案。救援碼輸錯也算進失敗次數。

## 已決定的做法

- **Finder 整合**（Claude 決定）：用 macOS「快速動作」做右鍵選單，選到的檔案交給 AirSign App 處理。
- **加密**（Claude 決定）：
  - 每個檔案用自己的隨機金鑰，以 AES-GCM（CryptoKit）加密。
  - 這把檔案金鑰再用一把「主金鑰」包起來，跟密文一起存在 `.airsign` 檔裡。
  - 主金鑰存在 macOS 鑰匙圈，只有簽名比對通過時 App 才會取出來用。
  - 檔案金鑰另外再用「救援碼推導出的金鑰」包一份，也存在 `.airsign` 檔裡，所以救援碼在任何 Mac 上都能開檔。
  - 好處：更換簽名不必重新加密任何檔案；`.airsign` 檔被複製到其他電腦，沒有救援碼就打不開。
- **簽署與鑰匙圈**（Claude 決定）：用免費 Apple ID 的個人團隊簽署，讓 App 每次重新建置後身分不變。**實作第一步**就要驗證：重新建置後讀鑰匙圈不會跳出密碼視窗。不行的話，改用只有這個 App 讀得到的加密檔存主金鑰，並寫進威脅模型。
- **檔案處理**（Claude 決定）：
  - 上鎖：寫好 `.airsign` 並驗證後，把原檔**移到垃圾桶**而不是直接刪除，避免 demo 時弄丟檔案。限制是垃圾桶裡還有明文，要寫進威脅模型。
  - 解鎖：還原原檔，把 `.airsign` 移到垃圾桶。
- **比對方法**：沿用原型的 DTW（動態時間校正）。（下面有細節）
- **簽名樣本**：存在本機，用另一把鑰匙圈金鑰加密保存，不上傳。
- **Demo 模式**（Claude 決定）：
  - 開啟時：顯示簽名路徑、每道關卡的分數和哪一道沒過，給 demo 用
  - 關閉時：只顯示通過或無法辨識，避免把線索透露給攻擊者

## 比對方法（來自原型實測）

**每筆資料的特徵**
- 陀螺儀 3 軸（除以 3 rad/s）
- 扣掉重力的加速度 3 軸（除以 0.5 g）
- 重力方向 3 軸

**怎麼錄一次簽名**
- 開始：轉速超過 0.6 rad/s
- 結束：轉速低於 0.3 rad/s 並維持 0.5 秒
- 前後各保留 3 筆資料

**怎麼比**
- 用 DTW 比較兩次簽名，允許 25% 的時間伸縮，距離除以兩段長度總和。
- 時長差距也算進去：`距離 ×（1 + 0.5 × |ln(時長比)|）`
- 和每一個註冊樣本比，取最小值。

**多道關卡**：關卡 1 直接比對「同一副 AirPods、同一顆」，不符就拒絕。關卡 2–4 用上面的總分決定；顯示燈號時，分別用重力、加速度加時長、陀螺儀各算一次 DTW，跟註冊樣本彼此之間的差距比較，差最多的那一道亮紅燈。原型已經用總分做到四道關卡的效果，時長也有算進去；當時唯一缺的是把關卡 1 做成明確的檢查。

**實測證據**（`spikes/airpods-motion/sessions/` 裡 116 次嘗試）
- **第一輪**：只看握持角度（重力方向）就能 100% 分開本人和模仿者（AUC 1.00）。
- **第二輪**：模仿者學會握法之後，握持角度只剩 AUC 0.93，陀螺儀 0.92，加速度 0.91，全部特徵加起來 0.96。分數開始重疊。
  - 門檻 0.91：15 次模仿放過 12 次
  - 門檻 0.54：本人 10/10 通過，模仿只放過 1/15
- **簽名長度**：約 2 秒的簽名比約 6 秒的穩定很多。6 秒那一輪，本人自己就有將近一半被拒絕。
- **公平測試**：模仿者用「另一顆 AirPod」一定會被擋下，這要算在關卡 1，不能當成偽造防禦的成績。

**調整目標**（交給實作者調）
- 用至少 10 次本人、10 次「看過 3 次以上」的模仿來設定各關卡的門檻。
- 目標：本人通過 ≥ 9/10，模仿通過 ≤ 1/10。
- 第二輪數據顯示：一旦握法被學走，節奏（陀螺儀）要占更大權重。

## 威脅模型（demo 和 Q&A 都要用）

| 攻擊者 | 擋得住嗎 | 原因 |
|---|---|---|
| 拿到 `.airsign` 檔案（被複製、被寄走） | 擋得住 | 主金鑰只在擁有者這台 Mac 的鑰匙圈裡 |
| 趁你離開時用你已登入的 Mac | 擋得住 | 要通過四道關卡，連錯 5 次會被鎖住 |
| 偷走你的 AirPods | 擋得住 | 還需要你的握法和節奏 |
| 看過你簽名後模仿 | 部分 | 第二輪實測有重疊，要靠節奏關卡和較嚴格的門檻；demo 時誠實展示數字 |
| 錄下動作資料重播 | 大致擋得住 | 資料直接來自系統讀取的實體 AirPods；要偽造必須能在你的 Mac 上執行程式 |
| 知道你的 Mac 登入密碼、又有技術能力直接讀鑰匙圈 | 擋不住 | 簽名是門鎖，不是金鑰本身；未來用 fuzzy extractor 讓金鑰直接由簽名產生 |
| 翻垃圾桶裡上鎖前的原檔 | 擋不住 | 第一版為了安全把原檔移到垃圾桶；要提醒使用者清空 |
| 拿到救援碼加上 `.airsign` 檔 | 擋不住 | 救援碼等同萬能鑰匙，要離線保管；輸錯會計入失敗次數 |
| 擁有者自己弄丟 AirPods | 不會鎖死 | 用救援碼開檔，再用新的 AirPods 重新註冊 |

## 交給實作者決定

- **App 架構**：建議做成單一個原生 macOS App（Swift + SwiftUI），內含：讀取動作資料、比對、加密、簽名視窗、安裝快速動作。也可以沿用原型「Swift 讀資料 + 網頁介面」的做法。
- 快速動作怎麼把檔案路徑交給 App：URL scheme、命令列參數或本機連線都可以。
- `.airsign` 檔的格式細節：檔頭、版本、原檔名、被包起來的金鑰、nonce。
- 各關卡的特徵權重、門檻和調整流程。
- 畫面視覺設計。
- 是否支援一次選多個檔案。
