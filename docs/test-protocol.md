# AirSign 多輪測試計畫

這份測試要回答三個問題：
1. **不可模仿性**：別人模仿得出你的空中簽名嗎？
2. **系統安全**：加密和防護在真實攻擊下有沒有守住？
3. **最佳門檻**：門檻倍數設多少，最能兼顧「本人好過」和「模仿者過不了」？

可以拿去給評審的說法：**「對這幾位模仿者而言」，模仿 100 次、0 次通過，有 95% 的把握每次的成功率低於約 3%**（三分之一法則，單尾 95% 上限，0/100 → 2.95%；用 Wilson 區間則是 3.7%，報告時要寫明用哪一種）。以原型測到的比率（約 1/23），**很可能會出現非零的結果**，所以也要準備「x/n，Wilson 95% 區間」的說法。

## 凍結的比對方法（2026-11-07 18:00 ET 起，不再更動）

- **主要方法 = 目前 App 的做法**（`baseline`，倍數 1.25），已經在今晚測試前 commit。所以今晚**所有**的模仿嘗試，對主要方法而言都是沒看過的資料。
- 最多再比較三個事先指名的挑戰者，規則見 [algorithm-bakeoff.md](algorithm-bakeoff.md)。
- 揭露：C 同時是模仿者和分析者，報告裡要寫出來。

## 準備（每台 Mac 各一次）

1. 安裝最新版：
   ```bash
   cd airsign && scripts/install.sh
   ```
2. 先用 ⌘Q 關掉 AirSign，再用測試模式啟動：
   ```bash
   open -a AirSign --args --test-mode
   ```
   畫面頂端會出現紅色的 TEST MODE 橫幅。一般方式開啟（雙擊、右鍵）時，App 完全不會進入測試模式。
3. 按「Open test lab」，**由本人簽一次**才能進入測試實驗室。
4. **只在 S1 開始時**，本人按 **Re-enroll owner (logged)** 重新註冊 3 次，讓註冊的原始資料也被記錄。**S2、S3 不要重新註冊**，一直沿用 S1 的註冊樣本，這樣才量得到「睡醒後、隔了幾小時」本人還過不過得了。
5. 每台 Mac 在 S1 開始前量一次取樣率：用測試模式簽一次後，看最新記錄的 `rows` 筆數 ÷ `dur` 秒數（AirPods Pro 3 預期約 50；AirPods 4 可能只有 25）。

**測試實驗室的規則**：嘗試只做驗證、不會開任何檔案，所以**不會計入連錯鎖定**。解鎖檔案、救援碼、更換簽名這些正常流程仍然有鎖定保護。

## 角色

| Mac | 本人 | AirPods | 模仿者 |
|---|---|---|---|
| Mac 1 MacBook Pro | Eric | AirPods Pro 3，右耳 | B、C |
| Mac 2 MacBook Air | B | AirPods 4，用 B 的慣用手那一側 | Eric、C |

## A. 不可模仿性（每次嘗試都會自動記錄）

在測試實驗室填好 **Owner**、**Tester**、**Session**、**Scenario**，按空白鍵簽名。畫面會顯示每個場景已經測了幾次（目前次數／目標次數）。

| 場景 | 誰簽 | 怎麼做 | 每人每時段的目標次數 |
|---|---|---|---|
| A1-owner | 本人 | 自己的簽名，照平常的方式 | 20 |
| A2-zero-effort | 模仿者 | 簽自己的名字，不模仿 | 10 |
| A3-watched-once | 模仿者 | 在旁邊看本人簽一次，然後模仿 | 10 |
| A4-skilled | 模仿者 | 用手機在 1 公尺外錄下本人簽名、看 3 次，事先被告知握法和簽名平面，再自己練 5 分鐘（練習時不開實驗室）。**S1 做 15 次、S3 做 10 次**；S3 時模仿者**看不到螢幕**，由本人操作電腦、螢幕轉開，避免模仿者用 S1 看到的分數和燈號練習 | 25 |
| A5-other-bud | 本人 | 自己的簽名，但換用另一顆 AirPod | 10 |
| A5-other-pair | 本人 | 自己的簽名，但換用另一副 AirPods（兩台 Mac 的 AirPods 互換） | 10 |

**公平規則：**
- 除了 A5 以外，模仿者都用**本人那一顆** AirPod。另一顆放在充電盒裡，手指要蓋住感測器。
- A4 的模仿者在實驗室裡看得到分數和燈號，這比真實攻擊者拿到的資訊還多，所以這是**偏嚴格的測試**。
- 如果出現「Discarded」（手指滑開、太短），那次不會被記錄，重簽就好。

**時段：**

| 時段 | 時間（美東） | 要做什麼 |
|---|---|---|
| S1-tonight | 19:00–21:00 | 全部場景 |
| S2-midnight | 00:00 前後 | 只做 A1，每位本人 20 次（不重新註冊） |
| S3-morning | 07:30 | A1 每位本人 20 次，加上每位模仿者 A4 10 次（看不到螢幕），再補完還沒達標的場景（不重新註冊） |

**每個時段都要記**：每位測試者、每個場景出現幾次「Discarded」（手指滑開、太短）。App 不會記錄這些，請用紙筆或手機記下來，報告時要寫出被排除的次數。

S1、S2、S3 的 A1 結果放在一起比較，就能知道**睡醒後本人的通過率會不會下降**，也就是握持角度要不要校正。

## 資料怎麼交給 C

每個時段結束後，在每台 Mac 執行：
```bash
cd ~/Library/Application\ Support/AirSign && zip -rq ~/Desktop/airsign-test-logs-$(hostname -s)-S1.zip test-logs
```
（S1 換成當下的時段）用 Discord **私訊**傳給 C。這些是簽名資料，**絕對不能 commit 進 repo**。

## C 的分析要產出什麼

寫進 `docs/evaluation.md`：
1. **各場景的通過率**：A1 本人通過率（分時段）；A2–A4 模仿者通過率；A5 應該 100% 擋下。
2. **門檻倍數**：**只用 S1 的本人資料決定**，不看模仿者的資料。選「S1 本人通過率 ≥ 95% 的最小倍數」，再**加 0.10 的保留空間**，然後套用到 S2、S3。本人通過率一律附上 Wilson 95% 區間；不要要求每格都 ≥ 95%，因為每格只有 20 次，即使真實通過率是 95% 的系統，四格全部達標的機率也只有約 29%。
3. **可以引用的結論**：「對這幾位模仿者而言：本人 x/n、隨便亂簽 y/n、練習過的模仿 z/n，附 Wilson 95% 區間」。只有 S1 可以報 EER；S2、S3 的 EER 要標明是偏樂觀的估計。
4. **兩張圖**（給 Devpost 和簡報用）：本人和模仿者的分數分布圖、門檻倍數對通過率的曲線。

每筆記錄都有 `enrollment` 欄位（註冊樣本的指紋），驗證時要拿同一個 `enrollment` 的 `mode: "enroll"` 記錄當作樣本。
